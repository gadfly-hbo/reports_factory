## Problem Statement

用户试用 Report Studio 后的体感是「完全不是我想要的」，并裁定方向：**这是一个报告生成器**，期望的用法是「选模版 → 传资料 → 一键生成 PPT/文档 → 改单页 → 审批导出」。现状是 5 阶段编审流水线（材料→编审→组装→检查→导出）逐步点表单，采证/冲突/口径等内部机制暴露为主路径，人既做决策又做流程搬运——「完全不是想要的」根因即产品形态方向不对（KA-1 由此裁定回答）。

约束（用户裁定）：内部细节（采证、审批机制本身）不为此重构；但**外发和内部使用审核必须保留**。

## Solution

模版驱动的一键生成形态，四步主路径：

1. **选模版**：内置模版库（多套可选，含结构预览与适用场景）。
2. **一键生成**：上传资料 + 选模版 + 一键 → 程序管线自动完成大纲→组装→检查（确定性为主、AI 显式开关），进度可见、失败/超帽停在明示断点。
3. **改单页**：文字为主——直接改（标题/正文）或给 LLM 提示词重新生成单页；图片插入/替换可用（后置优先级）。
4. **审核审批**：导出前体检 + 内用/外发审批（复用既有 G1/导出确认/ack 机制）→ 导出 PPT/文档。

职责三分保持：AI 推进生成（阶段工人、单页重生成），产品守住围栏（出站白名单/批准门/预算三线封顶/审计），人在审核审批关口做决策。

## User Stories

1. 作为报告生产者，我想在一个模版库里看到多套报告模版（结构预览 + 适用场景），以便生成前选对形态。
2. 作为报告生产者，我想上传资料后点一次「一键生成」直接得到 PPT/文档成稿，以便不用走 5 阶段表单流。
3. 作为报告生产者，我想在一键生成过程中看到当前进度（解析/大纲/组装/检查哪一步），以便知道系统在干什么。
4. 作为报告生产者，我想让生成失败或预算超帽时停在明示断点并可重试，以便不从头再来。
5. 作为报告生产者，我想直接在单页上修改标题和正文文字，以便快速微调。
6. 作为报告生产者，我想给 LLM 一句提示词让它重新生成当前单页（标题/要点/表格注释），以便大改一页时不用手写。
7. 作为报告生产者，我想在应用 LLM 整页草案前看到逐条差异并确认，以便模型永远没有直写通道。
8. 作为报告生产者，我想调整页序、换版式、删页/拆页，以便生成后先调结构再逐页改。
9. 作为报告生产者，我想把上传的图片插入或替换到指定页，以便报告图文兼备（文字为主）。
10. 作为报告生产者，我想在导出前跑一键体检并看到问题清单，以便带着全绿结果去审批。
11. 作为报告生产者，我想在导出时区分内部使用与外发，外发需显式勾选确认，以便外发物经我放行。
12. 作为报告生产者，我想保留内容审核（G1 签批）在主路径上的清晰关口，以便内用/外发都有责可追。
13. 作为报告生产者，我想导出 PPTX/PDF/DOCX/HTML 任一格式，以便适配不同交付场景。
14. 作为报告生产者，我想看到本次生成与 AI 操作的调用计量与预算余量，以便成本可控。
15. 作为报告生产者，我想让预算超帽即停并明示（次数/时长/轮次），以便不静默烧钱。
16. 作为报告生产者，我想让每次 AI 调用仍过出站批准门（首次预览 payload），以便隐私围栏不松动。
17. 作为报告生产者，我想让模型不可用时生成/重生成自动回退确定性版本并明示，以便主线不被模型故障卡死。
18. 作为报告生产者，我想让采证/冲突/口径等高级详情收进二级面板（不删除），以便主路径干净又不丢能力。
19. 作为报告生产者，我想让每次编辑与 AI 操作留有审计记录，以便事后核查。
20. 作为测试维护者，我想让管线停点、预算门、批准门有负例测试，以便围栏不被一键化悄悄削弱。
21. 作为测试维护者，我想让生成与 AI 重生成有夹具回放测试，以便改动以回放全绿为完成定义（P6）。

## Implementation Decisions

### D1 模版注册表（新）

- 模版 = 结构预设 + 品牌 token 预设：`{ id, name, description, deliverable_type, page_plan(页型序列), brand 预设 }`。
- 首批 3 个模版：**经营复盘 deck**（现有 8 页复盘主线）、**执行摘要 deck**（meeting_deck/executive_summary）、**研究报告 doc**（research_report 7 节主线）——复用既有 composeOutline 两条主线与 8 页型语义骨架。
- **不做**任意模版导入设计器（M3 红线「滑坡成模板编辑器即失败」延续）；brand 层（M3 token 级）原样复用。

### D2 一键生成管线（新）

- `POST /api/projects/:id/generate`：ingest（幂等复用）→ outline（**确定性** composeOutline 按模版 page_plan）→ assemble（确定性）→ checks（确定性）→ 成稿可编辑状态。AI 不参与默认一键路径（可预测、零 token、离线可测）。
- 阶段状态持久化：管线每阶段落 checkpoint（阶段、产物、失败原因），失败/超帽停在明示断点，支持**断点续跑**（重试从失败阶段继续）。
- 一键管线是「程序循环」：阶段流转由确定性代码判断，**禁止 tool-call 循环**（红队 KA-5）。

### D3 单页编辑

- 补 body 直改入口（EditOp `edit_text` 已支持 body，UI 补上）；结构操作 UI 补全：reorder / switch_layout / split_page / 新增 `delete_page` op（同走 /propose 控制器：expected_revision 409、锁、原子应用、审计，不变式零改动）。
- **LLM 整页重生成**（核心）：扩展现有 ai-proposal（现仅 headline）到整页最小 op——`{ headline, bullets, table_note? }`，仍经 zod 强校验 + page_id 白名单 + /propose 确认应用（`source: 'model-draft'`）；prompt 约束与程序白名单双防线不变。
- 撤销 UI 本期不做（修订历史已在，后续可加 undo）。

### D4 图片编辑（文字为主，优先级后置）

- PageSchema 增 `image` 字段（上传资产引用 + 位置占位）；操作：插入/替换/移除；渲染三端适配（pptx addImage / html / docx）。
- 图片材料仍不解析（无 OCR，延续现状）；仅作为版面素材使用。

### D5 审核审批（复用既有机制，整理为主路径关口）

- 内容审核：G1 签批保留（批准人/冻结快照），未批准正式导出被拦、仅【草稿】可出。
- 导出审批：exportScope `internal|external`；外发默认禁止，需 `ack_external_share` 显式勾选 + 隐私检查；`ack_editable_data`/`chart_data_mode` 保留。
- 导出前体检：checks 全跑 + 问题清单可视化（blocker/warning 分列），全绿或明示遗留后才进审批。

### D6 预算与审计（红队 KA-3/标准 P4/P5 硬约束）

- **三线封顶默认启用**：调用次数（默认 50 次/会话）、墙钟（默认 30 分钟）、轮次（默认 20）；env 与项目级配置可覆盖。成本仅次级展示（小米 cost 恒 0，不作封顶依据）。
- 超帽：停在阶段边界/单页操作前，明示超哪条线、当前值/上限。
- 会话批准持久化：`projectId|mode` + 批准时间入 workspace，重启不失效；新项目/新模式仍弹预览。
- 审计：生成管线阶段事件 + AI 调用 + 门决策 + 编辑提案，零内容原则不变；P6 回放测试覆盖。

### D7 UI 形态

- 主路径四步：**项目/模版选择（含预览）→ 一键生成（进度条）→ 单页编辑（页面卡片列表 + 直改 + AI 重生成 + 结构操作）→ 审批导出（体检 + 内/外 + 格式）**。
- 五阶段视图降级为「高级」入口（不删除，story 18）；采证/冲突/口径收进材料详情二级面板。
- 视觉遵循 `~/.zcode/design/DESIGN.md`（暖灰纸底、铁橘 accent、mono 编号、分段控件）。

### D8 seam

- 复用：workbench 服务层 API、`modelClient()` replay/真实 transport 切换点。
- 新增 seam 仅一处：一键生成管线的服务边界（对外 `generate/checkpoint/resume`），模型行为测试全部经 replay 离线。

## Testing Decisions

- **好测试标准**：断言外部行为（管线停点/产物/门拦截/预算封顶/回退明示），不 mock 内部协作对象。
- **测试对象**：
  1. 模版注册表与选择（3 模版 page_plan 映射到组装产物）；
  2. 一键管线——阶段串联、断点续跑、失败停点、无 AI 依赖（默认路径零模型调用断言）；
  3. 单页编辑——delete_page 新 op、body 直改、LLM 整页重生成的白名单/schema/锁负例；
  4. 预算门——三线各自超帽负例 + 成本线不阻断负例；
  5. 审批——G1 未批拦正式导出、外发未勾选拦截、体检清单；
  6. 围栏回归——既有 tests 全绿（白名单/schema/兜底零破坏）；
  7. 回放——recording.ts 夹具 record→replay 闭环（P6）。
- **先例**：tests/ai-*.test.ts 录制重放、render-contract、regression golden、page-types 全页型渲染。

## Out of Scope

- 任意 PPT 模板导入设计器（M3 红线）。
- tool-call agent 循环 / 拴绳主导模式（§5 裁决不变）。
- 采证/冲突/口径内部机制的重构（只收起露出，不改机制）。
- 图片 OCR/内容解析、图片裁剪编辑器。
- 撤销/版本对比 UI（修订历史已够审计，undo 后续可加）。
- 模型 prompt 质量大改、换模型（KA-2 若不过另行立项）。
- 多用户协作批准模型、Windows 真机验证（沿用既有声明缺口）。

## Further Notes

- **KA-1 已由用户方向裁定回答**：根因 = 产品形态方向（应为模版一键生成器），本 PRD 即目标形态。
- **KA-2 降级**：默认一键路径全确定性，不依赖模型质量；LLM 整页重生成为显式点选增强，草案质量风险限于该入口（仍有差异确认把关）。
- **红队硬约束落点**：KA-3 → D6 三线封顶；KA-4 → 主路径关口即「审核审批」（决策）与管线自动推进（例行）两分；KA-5 → D2 禁 tool-call 循环。
