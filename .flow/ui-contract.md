## 1. Surfaces

| 路由 | Surface | 说明 |

| `/project/:id/upload` | S3 第 1 步 上传资料 | |
| `/project/:id/understand` | S4 第 2 步 读取理解 | |
| `/project/:id/framework` | S5 第 3 步 确认框架 | |

### S1 项目列表（ProjectsView 演进）

- 页头：eyebrow + 大标题「项目」+ 副题「上传资料 → 确认 PPT 框架 → 生成 → 逐页编辑 → 审核发布；数据默认只保存在本机。」
- 列表 table：名称（点击进入该项目当前步骤）/ 进度（mono 步骤徽）/ 更新时间 / 操作（删除 → M-1 确认对话框）。**只列 PPT 项目**；旧 `data/proj_*` 不出现、无入口，数据文件保留不删（G6）。
- 页内「新建项目」创建区（即 S2）。
- Trace: US14、US19、G6、ID1、ID5。

### S2 项目创建（S1 页内创建区）

- 字段：**项目名称**（必填，为空禁用「创建」按钮 + inline 提示）；**项目简介**（brief，可选，注明「用于生成 PPT 框架」——ID2 框架生成输入）；**框架模板**（G10：3 个框架模板三选一，默认选中第一项，附模板名 + 页序列倾向说明；沿用现 `/api/templates` 选择形态，内容按 PPT 框架改造——ID1）；**隐私策略**（F2 决议 M-U2：local_only（默认）/ external_ok 二选一，inline 注明「local_only 时 AI 调用被系统阻断」）。
- 创建成功 → 进入 `/project/:id/upload`。Trace: US14、ID1、ID2、G10、M-U2。

### S3 第 1 步 上传资料

- 上传区：虚线框空态语义（DESIGN `.empty`）+「＋ 上传资料」主按钮触发**文件多选** input；**不设前端格式白名单拦截**（US1「格式不限」），不支持的格式走解析失败明示路径。拖拽上传为可选增强（见 Affordances）。
- 已上传资料列表：文件名 / 类型徽（md、docx（Word）、pdf、图片、xlsx、csv 等，ingest 底座既有格式 + 新增 pdf/图片——ID1）/ 大小 / 上传时间 / 状态 / 操作（**移除**——F1 决议 M-U1；图片类型徽注明支持范围按 M-U4）。
- 主 CTA「开始读取理解」→ 进入 S4 并可启动理解（六步显式流程，理解由用户显式触发）。
- 图片：可上传（JPEG/PNG/GIF/WEBP，单张 ≤10MB——M-U4 调研定稿）；pdf：unpdf 文本提取（M-U5）。
- 重复/冲突文件：明示冲突提示，不静默覆盖（ingest/conflicts 沿用，ID1 保留清单）。
- Trace: US1、US19、ID1（ingest + 新增 pdf/图片）、ID5、M-U1、M-U4、M-U5。

### S4 第 2 步 读取理解

- 主 CTA「开始读取理解 / 继续理解」（显式触发）。
- 逐文件状态列表（G11 checkpoint）：待理解 / 理解中 / 已完成 / 失败。总进度「理解进度 N/M」（mono、tabular-nums）。
- 已完成文件可展开查看理解摘要（要点/数据要点，ID2 结构化 schema 摘要）——「人看得懂过程」（DESIGN 语义②），数据已由 G11 独立持久化。
- 失败文件：badge-warn「失败」+ 原因（格式不支持/文件损坏/超时）+「重试」按钮（单文件重跑，已完成文件跳过——G11）+「移除」（M-U1：移除后不再阻塞）。重进页面不丢 checkpoint。
- 全部完成后 CTA「进入确认框架」→ S5。存在失败文件时 S5 锁定并明示（移除或重试后解锁——M-U1）。
- 追加资料：可随时返回 S3 上传；新文件进入「待理解」，需重新完成理解；**已确认框架不因此解锁或失效**，新摘要仅作为后续 agent 改页的材料上下文（M-U3 决议回填）。
- Trace: US2、US13、ID2（逐文件单发理解摘要）、ID5、G11、M-U1、M-U3。

### S5 第 3 步 确认框架

- 进入条件：理解完成。空态（理解未完成时本步 locked，显示「先完成读取理解」+ 跳转链接）。
- 初始态：空态 + 主按钮「生成 PPT 框架」（材料摘要合集 + brief 单发生成——ID2；生成中显示「框架生成中」状态，US13）。
- 生成后：**整框架一屏确认**（G7）。框架行 = mono 页号（01…）+ 页题（行内 input 可改）+ 页型 badge + 意图说明（muted 小注）+ 来源提示（mono 元数据；schema `{page_id, title, page_type, intent, source_hint?}`——G7）。
- 行操作：**改题**（行内编辑）/ **删页**（→ M-2 确认）/ **调序**（上移/下移按钮）/ **加页**（追加框架行；**加页只在此屏存在**——G8）。
- 底部主按钮「确认框架」→ 确认后**框架锁定**（G7）：列表转只读 + badge「已确认」，无任何解锁控件；「开始生成」引导 → S6。
- 框架生成失败：区块内 fail 面板 +「重试」（单发失败重试）。
- Trace: US3、US4、US5、ID2（框架单发生成）、ID5、G7、G8、G10（模板倾向已作用于生成）。

### S6 第 4 步 生成

- 进入条件：框架已确认。未确认时本步 locked + 锁定原因（Negative case N1）。
- 初始态：框架摘要只读 + 主按钮「开始生成」（显式启动整套生成——US5「一键生成」以确认后单次动作启动整套实现，确认与启动分离以避免误触发长任务与预算消耗；六步显式流程语义）。
- 进行中：逐页状态列表（mono 页号 + 页题 + 状态徽：排队 / 生成中 / 已完成 / 失败）+ 总进度「生成进度 N/M 页」（US13）。生成在服务端按页推进、逐页 checkpoint；离开本页再返回进度不丢（ID2 断点续跑）。
- 中断恢复：重进显示已完成页 +「继续生成」（跳过已完成页，ID2 checkpoint）。
- 页级失败：失败页 badge-warn + 原因（含超时——pi-transport 超时，ID1 保留清单）+「重试该页」按钮；**只重试失败页，不全部重来**（US18）。
- 预算封顶触发：任务停止 + 区块内 fail 面板「已停止：调用预算达上限」（US16 围栏静默生效、越界时明示，不静默）。
- 完成态（全部页就绪）：CTA「进入逐页编辑」→ S7。存在缺失/失败页时 publish 保持锁定（发布对象为整套 PPT）。
- 生成进行中禁止重复启动（按钮禁用态）。
- Trace: US5、US6、US13、US18、ID2（逐页工人 + checkpoint）、ID5、G2（工人模式）、G12（单用户假设）。

### S7 第 5 步 逐页编辑

- 布局：页列表（mono 页号 + 页题 + 状态）+ 页编辑器 + Inspector 壳（S0.5）。
- **手工直改**：仅纯文字字段（G8）——页标题（headline）、要点逐条文本（bullets）、表格注释（table_note）、图表标题。编辑结果持久化（验收口径：刷新/重进后保留；保存时机为实现自由度）。手工输入内容不过滤 emoji（M-U6 决议：0 emoji 断言限于模型生成路径，用户手输是用户意图，导出物如实携带）。
- **只读区**：页型、版式、图表数据等非文字字段只读并注明「由生成决定，暂不支持手工修改」（G8 手工改=纯文字字段）。像素级预览非本期必需（可作增强，不作验收项——PRD 未要求，契约不发明）。
- **自然语言改页**：每页一个指令输入（label「让 agent 改这一页」+ textarea + 提交按钮「改写」）。提交 → 单发整页重生成（G8、ID2）；处理中输入禁用 + 状态徽「改写中」；成功后页内容整体更新。
- **改写被拒**（出站白名单 fail-closed）：区块内 fail 面板「本次改写被拒（出站白名单）：{原因/字段清单}」，常驻可见可重试（Negative case N4）。
- **删页**：页操作「删除页」→ M-2 确认；**锁定页与最后一页删除控件禁用并注明原因**（G8 沿用 M6 语义）。**本屏无「加页」控件**（加页只在 S5——G8）。
- Trace: US7、US8、ID2（单发变换 + 出站白名单 fail-closed）、ID5、G8、M-U6。

### S8 第 6 步 审核发布

- 顶部深藏青原则横条（DESIGN governance 语义）：「内用草稿随时可导；外发发布需隐私检查通过并经你批准——批准持久化留痕。」
- deck 概况：页数、最近生成时间（mono）。
- **隐私检查区**：按钮「运行隐私检查」→ 结果面板：通过（badge「通过」）/ 命中（badge-fail「命中 N 项」+ 明细列表：页号 + 位置 + 类型）。命中即 fail-closed：外发批准入口禁用、命中明细常驻可见（ID3：原 checks/privacy.ts 判定并入出站围栏，发布前整 deck 扫描——G9）。
- **批准区**：按钮「批准外发」→ M-3 对话框（明示：外发导出物可带出本机；批准将持久化留痕）→ 确认后 badge「已批准外发」。围栏判定批准失效（如内容变更）时显示「批准已失效，需重新批准」并引导重跑（fail-closed 可见）。
- **导出区**：层级分段控件（内用草稿 | 外发发布，DESIGN `.segment`，aria-pressed）+ 格式分段控件（PPTX | HTML | PDF）+「导出」按钮。
  - **内用草稿**：随时可导，无需检查/批准；导出物标记 draft（G9）。
  - **外发发布**：需「隐私检查通过 + 已批准」，否则按钮禁用 + 原因明示；服务端仍二次校验，拒绝时区块内 fail 面板「外发导出被拒：{原因}」（对应 Testing Decisions 围栏负例必测的 UI 呈现）。三种格式出自同一批准层级（G9）。
  - 导出完成：toast「已导出 {格式}（{层级}）」+ 下载；记录进入导出记录列表与 Inspector「导出与批准」。
- 导出物语义：PPTX 原生可编辑（US10，render/pptx.ts 复用）；HTML 单文件翻页幻灯片（US11，键盘/按钮翻页，纯静态——ID4）；PDF 逐页打印（US12，Playwright——ID4）。
- 发布状态徽（全站含 StatusBar）：未发布 / 内用草稿 / 已外发，如实标注（DESIGN 语义③）。
- Trace: US9、US10、US11、US12、US17、ID3、ID4、ID5、G9。

## 2. Click paths

每条按：主成功路径 / 加载态 / 空态 / 失败态（校验 / 网络 / 超时 / 围栏）。反馈通道约定：表单校验 = inline；瞬时结果 = toast；**围栏拒绝与任务失败 = 区块内 fail 面板常驻**（DESIGN「不隐藏失败」，不允许只用一闪而过的 toast）。

**S1 项目列表**
- 主：进入 `/` → 列表渲染 → 点项目名 → `/project/:id`（redirect 当前步骤）。
- 加载：列表区「加载中…」。空：虚线空态「还没有项目」+「新建项目」动作。失败：接口失败态 + 重试（不渲染假数据）。
- 删除：点「删除」→ M-1 → 确认后从列表移除并 toast；取消无副作用。

**S2 项目创建**
- 主：填名称（模板默认选中第一项，隐私策略默认 local_only）→「创建」→ 跳 `/project/:id/upload`。
- 校验：名称为空 →「创建」禁用 + inline 提示。网络/服务失败：inline 错误 + **表单态保留**（不丢已填字段）。模板接口失败：模板选择区降级为「模板加载失败，可稍后在框架屏调整」+ 仍可创建。

**S3 上传资料**
- 主：点「＋ 上传资料」→ 系统多选 → 逐文件入列（类型徽/大小/时间）→ CTA 进入 S4。
- 加载：列表初始加载「加载中…」。空：虚线空态「尚未上传资料」+ 上传动作。
- 失败：上传网络失败/超时 → 列表项标「上传失败」+ toast + 重试；不支持格式 → 解析失败明示原因（不静默丢弃）；重复/冲突 → 冲突提示；图片超限（>10MB 或不支持的图片格式）→ 明示原因（M-U4）。
- 移除：点「移除」→ 确认后文件与其摘要/checkpoint 一并删除（M-U1）；理解进行中的文件移除 → 取消该文件任务后删除。
- 取消：移除确认取消 → 无副作用。

**S4 读取理解**
- 主：「开始读取理解」→ 逐文件推进 → 全部完成 →「进入确认框架」。
- 加载：进行中文件状态徽「理解中」+ 总进度 N/M。空：无资料时显示「先在上传资料步骤添加文件」+ 跳转。
- 失败：单文件失败 → 明示原因 +「重试」（G11，已完成文件跳过）+「移除」（M-U1，阻塞可解除）；网络错误 → 面板重试；超时（pi-transport）→ 明示「超时」+ 重试；重进页面 checkpoint 恢复（G11）。

**S5 确认框架**
- 主：「生成 PPT 框架」→ 框架渲染 → 改题/删页/调序/加页 →「确认框架」→ 锁定 +「开始生成」引导。
- 加载：「框架生成中」（US13）。空：未到进入条件 → 锁定说明 + 跳转 S4；理解完成后未生成 → 「生成 PPT 框架」按钮。
- 失败：框架生成失败/超时 → fail 面板 + 重试；删页确认取消 → 无副作用；确认请求失败 → 框架不锁定 + 错误明示（fail-closed：未确认即未锁定）。

**S6 生成**
- 主：「开始生成」→ 逐页推进 → 全部完成 →「进入逐页编辑」。
- 加载：逐页状态 + 「生成进度 N/M 页」。空：框架未确认 → 锁定态（N1）。
- 失败：页级失败 → 该页标「失败」+ 原因（含超时）+「重试该页」（US18）；中断 → 重进「继续生成」跳过已完成（ID2）；预算封顶 → 停止 + fail 面板（US16）；网络/服务不可达 → 面板明示 + 重试。

**S7 逐页编辑**
- 主：选页 → 手工改文字字段（持久化）/ 输入指令「改写」→ 页内容更新。
- 加载：项目详情加载「加载中…」；改写中状态徽。空：无页 → 「先完成生成」+ 跳转 S6。
- 失败：改写被拒（白名单外字段）→ fail 面板明示原因（G8 fail-closed）；改写失败/超时 → 面板 + 重试或修改指令重提；手工编辑网络保存失败 → 明示 + 重试（不得静默丢弃输入）。
- 取消：M-2 取消 → 页保留。

**S8 审核发布**
- 主：「运行隐私检查」→ 通过 →「批准外发」（M-3 确认）→ badge「已批准外发」→ 选层级/格式 →「导出」→ 下载 + 记录。
- 加载：检查进行中状态徽；导出进行中按钮禁用 + 进行态。空：无导出记录 → 导出记录区虚线空态；deck 未就绪 → 本步 locked + 原因。
- 失败/拒绝：隐私命中 → fail-closed，命中明细常驻，外发入口禁用；未批准点外发（或服务端二次校验拒绝）→ fail 面板「外发导出被拒：{原因}」；批准对话框取消 → 无批准持久化，外发保持禁用；导出网络失败 → toast + 重试，不产生半条记录。
- 内用草稿：任一时刻可直接导出三格式，标 draft（G9），无需检查/批准。

**全局**
- 服务不可达（127.0.0.1 不可用）：状态栏/页面级明示「本机服务不可用」+ 重试，不渲染假内容。
- 项目加载失败：沿用 ProjectShell 现有失败态（「项目加载失败——可能已被删除」+ 返回项目列表）。
- 未知路由：兜底到项目列表。
- local_only 项目发起 AI 调用：围栏拒绝 → 区块内 fail 面板「项目隐私策略为 local_only，AI 调用已被阻断；可在创建区或 Inspector 调整」（M-U2 围栏的用户可见呈现，Inspector 提供策略切换）。

## 3. Affordances

- **输入控件**：全部表单 label 在上、输入在下（高 40px、radius 7px、line 边框），**不用 placeholder 代替标签**（DESIGN）。
- **上传交互**：文件多选 input 为必需路径（键盘可达）；拖拽上传为可选增强（实现时拖拽区须同时可点击触发 input，不得成为唯一上传途径）；不设前端 accept 白名单拦截（US1「格式不限」，不支持格式走失败态）。
- **框架编辑**：行内 input 改题；上移/下移按钮调序（键盘可达，拖拽排序为可选增强）；删除/加页为显式按钮；主按钮「确认框架」用 accent 实心 primary（DESIGN button-primary）。
- **键盘/焦点次序**：skip-link「跳到主工作区」（既有）为首个焦点；Tab 序 = DOM 序（TopBar → Sidebar → 主区 → Inspector → StatusBar）；⌘K/⌘B/⌘I 沿用；dialog 进入聚焦首控件、Esc 关闭、焦点返还；Palette 上下键 + Enter + Esc（既有）。
- **无障碍基线（DESIGN 优先）**：全站 3px accent 焦点环（button/input/…）；stepper 用 `aria-current="step"`、segment 用 `aria-pressed`；进度区 `aria-live="polite"`、失败通知 `aria-live="assertive"`；状态一律 badge 带文字，不只用颜色；数字 tabular-nums；`prefers-reduced-motion` 禁全部过渡；长标题/ID 给 title 或换行不截断。
- **层级/格式/视图切换**：segment 分段控件只切视图不清状态（DESIGN「视图切换只切视图」）。

## 5. Negative cases

**禁止路径**
- N1 框架未确认不可生成：S6 locked + 锁定原因；服务端同拒（ID2 人决策点围栏），前端如实呈现拒绝。人决策点仅两处——框架确认、审核发布（ID2），模型不可绕过，UI 不得提供绕行入口。
- N2 未批准不可外发导出：外发需「检查通过 + 已批准」；不满足时禁用 + 原因；服务端二次拒绝时 fail 面板明示（围栏负例必测项的 UI 呈现）。
- N3 隐私命中 fail-closed：外发批准入口禁用，命中明细常驻可见，无「跳过检查」「强制导出」类入口（DESIGN Don'ts）。
- N4 agent 改页白名单拒绝：fail 面板明示原因，可重试或改指令（G8 fail-closed）。
- N5 旧报告路由必须消失：`materials/outline/compose/check/export/ppt` 重定向不残留；CheckView / EditorialView / ComposeView / ExportView / GenerateView / MaterialsView / PptGeneratorView 不存在于代码树与 bundle（D1、ID1 删除清单）；Sidebar「高级」区与「快速 PPT」入口删除。
- N6 编辑层无「加页」控件（加页只在 S5）；锁定页与最后一页删除禁用并注明原因（G8）。
- N7 旧项目 UI 不可见：列表/侧栏/命令面板均不出现 `data/proj_*` 旧报告项目（G6，数据文件保留不删）。
- N8 local_only 项目不发生外部模型调用（服务端围栏强制）；UI 如实呈现阻断原因，不提供静默绕行（M-U2）。

**不得出现的状态**
- 任何页内容出现「待补充」占位（US6；M6 判定红线）。
- 报告工厂五阶段条（StageBar 旧阶段语义）任何残留。
- emoji 出现在**模型生成 / agent 改写**内容中（S-C 渲染缝 0 emoji 断言延续；手工输入不过滤——M-U6）。
- 假完成度：未发布/内用草稿/已外发、已确认/未确认、已批准/未批准一律 badge 带文字如实标注（DESIGN 语义③「如实披露完成度」）。
- 静默失败或静默调用：围栏拒绝与任务失败必须可见原因；未授权不静默调用模型或外发数据（DESIGN Don'ts）。
