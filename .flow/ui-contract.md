# UI Contract：Report Studio 对话式自主 PPT 工作台（v1 · UI-GATE 起草稿）

> 依据链：`.flow/proposal.md`（用户原始需求 + 关键裁决 + D1–D12）→ `.flow/prd.md`（US1–23 + GRILL G1–G8）。视觉基线：`~/.agents/ui-design/DESIGN.md`（token 见 §G，不另造色值/字体/圆角体系）。
> 范围：S5 前端工作台全部用户可见界面 = 壳层 W0 + 9 个 surface（W1–W9）。只钉用户可见结构、状态、文案与交互，不钉实现技术。旧六步 UI 退役由 §N 负面清单钉死。
> 起草：UI-GATE 独立子代理（2026-10-10）。可点击原型：`.flow/ui/index.html`（场景映射见 §P）。
> 产品名：Report Studio。界面语言：简体中文；产品名、模型名、工具名、代码与文件名保留原名。

### G.2 真实状态规则（全程硬约束）

1. 进度只来自真实事件（SSE 工具事件）：展示「当前在做什么」（工具名 + 目标 + 状态 + 完成耗时），**无百分比、无倒计时、无假进度条、无阶段配额**。
2. 任务状态文字可辨且带文字标识，区分：运行中 / 等待用户 / 失败 / 停止处理中 / 已停止 / 结果未知。颜色不独自表达状态。
3. 不展示模型隐藏思维链；展示的是工具调用与可见产出。
4. 等待原因真实：等待模型响应、等待渲染、等待导出各自可辨。
5. 未实现的控件一律不渲染为可点样式；禁用时说明原因与下一步。
6. 页面 HTML 预览一律明示「近似预览，非最终 PPTX 视觉」（proposal 边界条款）。

### G.3 壳层骨架（W0）

单窗口工作台，三区：

- **标题栏**：品牌「Report Studio」+ 项目名 + 原型/版本标签。
- **顶栏**：主区视图切换（「对话 / 成果」，成果未生成前禁用并说明）·「运行详情」按钮（开合右抽屉）·「设置」入口。
- **主体三栏**：左 = 项目侧栏（W1，250px 级）；中 = 主区（对话线程 W2/W3/W4/W9，或成果视图 W5/W6，或设置页 W8）；右 = 运行详情抽屉（W7，按需展开，不长期压缩主区）。
- **composer 常驻**于对话视图底部（W2），成果视图选中页后切回对话时保留页标记。

主区、侧栏、抽屉各自滚动，互不撑破。

Trace: US19、ID6、D12。

## 1. W1 项目侧栏

**用途**：多项目并行入口；旧六步项目不出现。Trace: US19、US23、G6、G7、D2。

**结构与内容**（自上而下）：

1. 「＋ 新建项目」按钮（紧凑，不做成装饰大卡）。
2. 项目列表：仅列重构后项目。项 = 项目名 + 会话时间（fine）。当前项目高亮（accent-soft 底 + brand 左描边）。
3. 当前项目下常驻「会话」入口 1 个（每项目一个持续会话，D2）：「会话 · 持续」+ 最近活动时间。
4. 项目项 hover 出现「删除」小按钮（危险动作）。
5. 底部固定 fine 注：「旧版六步项目已隐藏，数据仍保留在本机。」

**交互与状态**：

- 新建项目 → 命名（可留空，默认「未命名项目」）→ 创建并进入该项目空态（W9 空态）。
- 点击项目 → 切换当前项目（各项目独立会话与产物，G6）。
- 删除项目 → 确认弹窗（说明影响：「删除该项目及其会话与产物，不可恢复」）→ 执行后列表移除。这是全产品仅有的两种弹窗之一（另一种是删除确认同类）。
- 侧栏不出现：步骤编号、进度徽、向导导航。

## 2. W2 聊天主线程与 composer

**用途**：唯一任务入口——说需求 + 传材料；全程对话载体。Trace: US1、US2、US6、US9、US10、US12、US22、G2、G3、D10。

### 2.1 消息流

- **用户消息**：右对齐气泡；内含附件 chips（文件名 + 类型）。
- **AI 文本消息**：左对齐，无头像装饰堆砌。
- **工具动作卡**（对话流内联，来自真实事件）：工具名（如 `read` / `edit` / `render_deck` / `qa_deck` / `export_deck`）+ 目标（文件或页）+ 状态（运行中 → 完成（含耗时）/ 失败（含原因摘要））。
- **系统分隔**：服务重启恢复分隔线（W9）；会话历史完整保留。
- AI 等待响应时显示可辨等待态（「等待模型响应…」，wait 语义），不是通用转圈。

### 2.2 附件上传

- composer 左下「附件」按钮，支持 md / docx / pdf / csv / xlsx / 图片（US2）。
- 已传附件列表显示在 composer 上方：文件名 + 大小 + 解析状态：
  - 文本类：「解析中…」→「已提取 4,213 字」（G3：提取文本落盘，agent 读提取文本）；
  - 图片：「解析中…」→「已生成图片描述」（G3：vision 预理解 → 文字描述落盘）；
  - 失败：「解析失败：{原因}」+ 移除按钮，用户输入不丢失。
- 附件状态是真实状态，不在上传完成前假装就绪。

### 2.3 composer

- 多行输入框 + 主动作按钮，两种模式：
  - **空闲**：「发送」（brand 主按钮）。
  - **AI 运行中**：主按钮变「插话（steer）」+ 相邻「停止」按钮（fail 语义描边）。插话发送后显示确认说明：「将在当前工具步骤结束后送达」。停止点击 → 状态「停止处理中…」→「已停止（已完成部分保留）」。
- **页标记**：选中 deck 某页后（W5 触发），composer 上方出现徽标「针对第 N 页 · {页标题}」+ × 移除；带标记发送的消息由宿主注入页上下文（D10）。
- 生成中 composer 不锁定——这正是 steer 入口（US9）。
- 无材料也可直接发送（G2）：AI 会反问所需材料，或与用户确认「无数据版」框架。

## 3. W3 大纲提案卡

**用途**：核心差异化——AI 读完材料先发页面框架提案，人在卡片上定稿。AI 在对话中经 `propose_outline` 发出。Trace: US3、US4、US5、US6、US7、G1、G4、D9。

**卡片结构**（对话流内的 analysis-card）：

1. **头部**：「页面框架提案」+ 版本号（提案 v1 / v2 / …，每次按聊天意见重出新提案版本 +1，G4）+ 状态徽（待确认 / 已确认 / 已被 v{N} 替代）。
2. **页列表**，每页一行（或窄卡）：
   - 序号（按当前顺序实时重排）；
   - 标题：**内联可编辑**（点击即改）；
   - 页型徽（显示 agent 给出的页型词，如「封面」「对比」「图表」，不枚举固定集合）；
   - 意图一句话（intent）；
   - 来源标签（source_hint）：材料文件名或「无材料来源」（与 G2 QA 标注同语义）；
   - 行内操作：上移 / 下移（调序）、删除页。
3. 列表尾：「＋ 加页」→ 追加空白行（默认页型「内容」），同样内联编辑。
4. **待澄清问题区**（≤3 条，US5）：每条 = 问题文本 + 「去回复」按钮 → 将问题引文填入 composer（用户以自然语言回复，US6）。
5. **编辑状态**：卡片编辑即时保存为草稿；发生编辑后显示「已手动编辑」标记（fine）。卡片编辑保存 = 用户定稿，可直接确认（G4）。
6. **动作区**：
   - 「按此框架生成」（brand 主按钮）→ 确认，AI 全自主推进（US7），无逐步确认。
   - 次级引导：「有意见？直接在下方对话回复，AI 会重新出提案（版本 +1）」。
7. **确认后**：卡片状态变「已确认」，附一行 fine 说明：「框架不再锁定，后续增删改请直接在对话中提出」（G1：不锁定，页集合编辑 = 普通对话编辑）。
8. **旧版本**：新提案到达后，旧卡折叠为一行「提案 v{N-1} · 已被 v{N} 替代」（可展开查看，不可再确认）。

**负面约束**：不在卡外弹确认窗；不出现「锁定框架」按钮或仪式；不改用表单式逐页编辑器。

## 4. W4 生成进行态

**用途**：确认框架后 AI 全自主工作时的真实过程呈现。Trace: US7、US8、US9、US10、D10、G1。

- **生成状态条**（线程顶部或粘性）：当前真实活动，文案来自事件，如「正在读取材料：Q3销售数据.xlsx」「正在编辑 deck/pages/page_03.js」「正在渲染 deck（render_deck）」。禁止百分比/进度条/倒计时。
- **事件卡流**：随 SSE 事件追加：`read` / `edit` / `bash` / `propose_outline` / `render_deck` / `qa_deck` / `export_deck` 各工具调用 = 一张卡（工具名 + 目标 + 状态 + 完成耗时）；失败卡带真实原因摘要。
- **steer**：composer 保持可用（W2 运行中模式），插话即时可见并标注送达时机。
- **停止**：状态条与 composer 均有「停止」；停止后状态「已停止」，已完成页与工件保留，对话可继续（含「继续生成」的自然语言指令）。
- **完成**：AI 发完成消息（含页数摘要）+「查看成果」入口 → 主区切到成果视图（W5）。
- 确认生成后的其余推进**零弹窗**（US7、US22）。

## 5. W5 deck 工作区（成果视图）

**用途**：生成结果的逐页检查与逐页对话修改。主区顶栏切到「成果」。Trace: US11、US12、US13、US16、D8、D10、G1、G8。

- **视图头**：deck 名称 + 页数 +「返回对话」按钮。
- **页网格**：缩略卡 = 每页 HTML 近似预览（卡上固定 fine 角标「近似预览」）+ 页号 + 标题 + 状态（正常 / 渲染失败）。点选某页 → 大图查看（覆盖层或网格上方放大区），大图含页号、标题、来源标签，及按钮「针对此页对话」。
- **逐页修改**：「针对此页对话」→ 切回对话视图，composer 带页标记（W2）→ 用户对话修改 → 对话流可见 agent `edit page_XX.js` + `render_deck` 事件卡 → 完成后该页缩略图自动刷新（US13），全程无需用户操作渲染。
- **qa_deck 结果卡**（成果视图内，生成/重渲后展示）：结构校验结果逐项（通过 ✓ / 问题 ✗ + 说明）+ **建议性提示**（隐私/视觉，标注「建议」字样，不阻断任何操作，G8）+ 检查时间。
- **渲染失败页**：缩略卡红描边 + fail 文字「渲染失败：{原因}」+「在对话中重试此页」按钮（预填 composer，见 W9）。
- 确认生成后框架级增删改 = 普通对话编辑（G1），成果视图不提供「重新锁定框架」类控件。

### 5.1 成果视图内嵌页级 composer（flow-4 增补，用户反馈迭代①）

- 成果视图选中页时，大图下方内嵌页级修改 composer：页标记徽标（第 N 页 · 标题）+ 输入框 + 发送/插话（与 W2.3 同语义：空闲=发送，busy=插话+停止）；busy 内联等待态与工具卡；轮次结束留在成果视图、预览自动刷新，最近一轮回复以内嵌折叠摘要呈现（全文在对话视图）。
- 对话视图 composer（含附件）不变。

## 6. W6 导出区

**用途**：交付三格式 + 记录。位于成果视图底部（deck 工作区之下）。Trace: US14、US15、US16、G8、D8、ID3。

- **主动作**：「导出 PPTX」（brand 主按钮，原生可编辑文本/表格/图表）；次级按钮「导出 HTML」「导出 PDF」。
- **导出状态**（真实）：点击后按钮区显示「导出中（export_deck）…」→ 完成后记录列表新增一行；失败显示真实原因 + 重试。对话流同步出现 `export_deck` 事件卡。
- **导出记录列表**（沿用现有 exports 存储）：列 = 格式（pptx/html/pdf）· 时间 · 文件名 · 「下载」。下载状态各自真实呈现（可下载 / 生成失败），不以界面展示冒充已保存。
- **QA 关联**：导出区显示「最近 QA：通过 / 有建议（时间）」+ 查看入口；QA 建议不阻断导出（G8）。
- 无审批、无内外分级、无导出确认弹窗（G8）。

## 7. W7 运行详情抽屉

**用途**：透明可信——按需查看过程与账目。右抽屉，顶栏「运行详情」开合。Trace: US17、D6、D12。

- **页签 1「时间线」**：工具调用列表（新在上）：时间 · 工具名 · 模型（模型调用行显示模型名）· 耗时 · 结果状态（完成 / 失败 / 运行中，带文字）。零内容，不含文件正文。
- **页签 2「审计与成本」**：审计计数（模型调用 N 次 · 工具调用 N 次 · 写操作 N 次 · 导出 N 次；零内容 JSONL 审计的 UI 呈现，D6）+ 成本摘要（token 与费用，来自运行时真实事件；无记录时显示「本会话暂无费用记录」）。
- 抽屉展开不阻塞对话；关闭后焦点返回触发按钮。

## 8. W8 设置页

**用途**：模型链状态可见性。主区顶栏「设置」进入，仅此一页。Trace: US20、D3。

- **模型链**：
  - 主模型：MiniMax-M3（minimax-cn · anthropic-messages）——密钥就绪 ●（ok）
  - 备用模型：mimo-v2.6-flash（xiaomi · openai-completions 反向配置）——密钥就绪 ●
  - 未就绪时：○（wait）+ 文字「未检测到密钥」+ 下一步说明「请在宿主环境配置密钥后重启服务」。
- **密钥零内容**：界面不显示、不接受任何密钥内容；仅一行说明密钥来源：「密钥由宿主环境提供（环境变量 / `~/.pi/agent/auth.json`）」。
- 只读说明行：会话按项目持久保存于本机 `data/<proj>/session/`，服务重启后自动恢复（呼应 US18）。
- 设置页不做模型切换、不做参数调优表单（超出 PRD 的能力不提供假入口）。

## 9. W9 空态与失败态

### 9.1 新项目空态
主区中央引导（非弹窗）：「描述你要做的 PPT，并上传相关材料」+ 支持格式一句话 + fine 提示「也可以先不传材料直接描述，AI 会向你确认所需材料，或先出『无数据版』框架」（G2）。composer 聚焦。Trace: US1、G2。

### 9.2 AI 失败态（对话流内失败卡）
真实原因三选一呈现（US21）：模型不可用（含主备均失败的错误摘要）/ 预算外失败 / 工具错误（含失败工具名）。附可行下一步按钮：「重试」与「补充材料或修改要求」（后者聚焦 composer）。用户已输入内容不丢失。失败不用关闭窗口表达。

### 9.3 部分页失败态（成果视图）
失败页缩略卡标注原因（如「page_05.js 执行超时」）+「在对话中重试此页」→ 切回对话、composer 预填「请重试渲染第 N 页」并带页标记。其余页不受影响，正常可导出。Trace: US21、D10。

### 9.4 服务重启恢复态
重开页面后线程顶部出现分隔线：「服务已重启 · 会话已从历史恢复 · {时间}」，历史消息、附件、提案卡、deck、导出记录完整可见（US18、D2）。重启时若生成中断：显示中断说明卡「上次生成因服务重启中断」+「重试」；不假装任务仍在运行（结果未知 → 明示未知）。Trace: US18。

### 9.5 等待用户态
AI 反问材料或等待框架确认时，状态条显示「等待你的确认 / 等待你补充材料」，composer 主按钮恢复「发送」。Trace: G2、US5。

## P. 原型说明与场景映射

**文件**：`.flow/ui/index.html`（入口）+ `.flow/ui/styles.css` + `.flow/ui/app.js`。纯静态、零依赖、零构建，`file://` 直接打开。

**合成声明**：页面顶部固定横幅声明本原型为合成演示（不连后端，数据非真实）；顶部「场景切换器」与「推进演示事件」按钮为**非生产控件**（明显标注，生产实现中不存在），沿参考样例 review-controls 先例。

**场景 ↔ surface 映射**：

| 场景（切换器） | 演示内容 | surface |
|---|---|---|
| 空态 · 新项目 | 空态引导、composer 聚焦 | W9.1 |
| 首轮对话 · 附件已传 | 消息流、附件解析状态、读取事件卡 | W2 |
| 大纲提案卡（v2） | 内联编辑、增删调序、≤3 问题、版本折叠、确认按钮 | W3 |
| 生成进行态 | 真实事件流、状态条、steer、停止 | W4 |
| 成果 · deck 工作区 | 页网格、大图、页标记、QA 卡 | W5 |
| 成果 · 已导出 | 三格式按钮、导出记录列表 | W6 |
| 失败态 | 模型不可用真实原因 + 重试/补材料 | W9.2 |
| 部分页失败 | 失败页标注 + 在对话中重试 | W9.3 |
