# 提案：模版驱动一键生成——Report Studio 简易形态改造

> 来源：2026-10-05 用户试用反馈 + 方向裁定。诊断阶段曾提出「编排既有六阶段流水线的工人模式编排」方案，**用户裁定改用更简便的形态**：本提案取代编排器方向，是后续 PRD / GRILL / 拆解的根规范源（优先级高于 prd.md 与执行建议）。
> 保留自诊断阶段且用户确认的上位原则：AI 推进流程、产品承担围栏、人负责决策（AGENTS.md 职责三分）；但落地形态从「流水线编排」改为「模版驱动一键生成」。

## 用户方向裁定（verbatim 要点）

用户原话要点（2026-10-05）：

> 「这个是报告生成器，本质上不需要再去改里面的细节内容（比如：采证，审批）啥的，当然外发和内部使用需要审核。」
>
> 1. 有很多报告模版可以选择
> 2. 上传相关资料，然后选择报告模版，一键直接生成 PPT 或其他格式文档
> 3. 以 PPT 为例，可以修改每一页 PPT 的内容，文字或图片，文字为主；提供直接在 PPT 上修改或者给 LLM 提示词，让 LLM 重新生成单页 PPT
> 4. PPT 内容审核，外发或内部使用审批
>
> 「另外，还有哪些功能，你觉得必要的，可以加，这样就很方便也很实用」

## 方向解读（约束）

- **产品定位 = 报告生成器**，不是编审流水线产品：主路径是「选模版 → 传材料 → 一键生成 → 改单页 → 审批导出」。
- **不动内部细节**：采证、冲突处理、口径等内部编审机制不作为主路径展示内容，不为此重构；但既有的内用（G1/草稿）与外发（exportScope+ack）审批**必须保留**。
- **一键 ≠ 绕门禁**：一键生成把原材料→成稿的流程性步骤程序化（AI/确定性推进），审批与围栏仍在决策点停下——职责三分不变：AI 推进生成、产品守住围栏（出站白名单/批准门/预算/审计）、人做审批决策。
- 既有五个 AI 用点与围栏资产（outbound 白名单、privacy-gate、zod schema、id 白名单、确定性兜底、/propose 控制器）复用不削弱。

## 核心功能（用户已定，四项）

1. **多报告模版可选**：内置模版库，生成前选择；模版=页型序列/结构预设 + token 级品牌样式（复用 M3 brand 层，不做任意模板导入设计器——M3 红线「滑坡成模板编辑器即失败」延续）。
2. **上传资料 + 选模版 + 一键生成**：把现有 5 阶段 UI 流（材料→编审→组装→检查→导出）压缩为一键管线（确定性组装为主、AI 阶段工人为辅、程序自动串联），生成进度可见。
3. **单页编辑**：文字为主——直接改（标题/正文，现有 EditOp 控制器）或给 LLM 提示词重新生成单页（扩展现有 ai-proposal，从仅 headline 扩到整页重生成，仍走 /propose 白名单+确认应用）；图片编辑（插入/替换）列入范围但文字链路优先。
4. **审核审批**：PPT 内容审核（检查 + 内用/外发两级审批）——复用既有 G1/导出确认/ack_external_share 机制，整理为主路径上的清晰关口。

## 我建议补充的必要功能（待用户在 diff 门勾选/删减）

- **A. 模版选择页 + 预览**：每模版缩略结构（页型序列）与适用场景说明。
- **B. 生成进度与断点续跑**：一键生成的阶段进度条（当前在组装/检查哪步），失败/预算超帽停在明示位置可重试。
- **C. 单页 AI 重生成扩到正文**：现 ai-proposal 仅 headline；扩到整页（headline+bullets+表格注释），保持最小 op、白名单、确认应用。
- **D. 大纲级调整**：页序 reorder（EditOp 已有）+ 删页/换页型，UI 入口补上——生成后先调结构再逐页改。
- **E. 导出前一键体检**：既有 checks 全跑 + 问题清单可视化，全绿才放行审批（内用/外发）。
- **F. 图片素材能力**：上传图片插入/替换到指定页（文字为主，图片为后置切片）。
- **G. 预算/调用指示**：生成与 AI 单页操作的调用计量展示 + 封顶（延续红队 KA-3：次数/墙钟/轮次三线，成本仅次级参考）。
- **H. 变更历史/撤销**：单页编辑走 /propose 已有修订与审计，补 UI 撤销入口（undo 最近一次编辑）。

## 否决的方向（本轮）

- **六阶段流水线编排器改造**（上一版 proposal）：用户裁定改用更简便的模版一键形态；不再实现独立编排状态机。
- **任意 PPT 模板导入设计器**：M3 红线延续。
- **tool-call agent 循环 / 拴绳主导**：§5 裁决不变，仍为工人模式。

## 约束

- AGENT-RUNTIME 标准适用：单发 completion + schema 校验、无 tool-call 循环；预算三线封顶（KA-3）；审计可回放（P6 回放测试）。
- 全局 UI 设计规范 `~/.zcode/design/DESIGN.md`（铁橘 token、mono 编号）。
- gated dev-flow：评估 → PRD → 拆解 → **动工审批门**（用户批准切片后才 IMPLEMENT）。
- 技术栈沿用：TypeScript、pi-ai 0.86.x 钉版、zod、Fastify、React 19。
