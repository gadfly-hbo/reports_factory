# 场景配方：技术与架构评审
> 架构评审/技术方案/故障复盘——图先行、决策留痕、风险量化，工程师受众

## 页幅与逐页布局配方

**篇幅**：评审版 8-12 页。

**P1 封面**：方案名 + 评审类型 chip（新方案/改造/复盘）+ 作者/评审人/日期。
**P2 背景与目标**：现状痛点 3 条（每条量化：QPS/延迟/成本数字）+ 目标表（指标/现状→目标/衡量方式）+ 非目标（明确不做什么，line 灰框）。
**P3 现状架构**：模块框图（rect + 连线 + 标注：协议/QPS）；瓶颈点用 accent1 虚线框圈出 + accent1 实心小三角标注。
**P4 目标架构**：同 P3 风格的新架构图；变化点用 accent1 高亮 + 编号①②③，右侧变更说明列表一一对应。
**P5 方案对比**：3 方案对比表（维度：复杂度/成本/性能/风险/迁移成本，行 = 方案，推荐行 accent1 左边条 + 「推荐」chip）；底部决策理由 2 行。
**P6 关键设计**：每页 1 个设计点：时序图（泳道 3-4 条纵向 + 箭头消息）或状态机（圆角 rect + 迁移箭头）+ 3 行设计取舍（选了 X 因为 Y，放弃 Z 因为 W）。
**P7 数据与容量**：容量推演表（预估量级 → 资源需求 → 成本/月）；分库分表/索引策略要点。
**P8 迁移计划**：灰度时间线（1%→10%→50%→100%，每档回滚判据数字）+ 双写/回滚开关示意。
**P9 风险清单**：表（风险/概率 chip 高中低/影响/缓解）。
**P10 里程碑与 Ask**：排期横条 + 需要的决策/资源。

## 特有组件

```js
// 模块框（架构图节点）
const box = (x, y, w, name, qps) => {
  slide.addShape('rect', { x, y, w, h: 0.6, fill: { color: t.light }, line: { color: t.primary, width: 1 }, rectRadius: 0.05 });
  slide.addText(name, { x, y: y + 0.05, w, h: 0.3, fontSize: 12, align: 'center', bold: true });
  slide.addText(qps, { x, y: y + 0.32, w, h: 0.25, fontSize: 9, align: 'center', color: t.muted });
};
// 泳道时序：纵线 + 箭头
slide.addShape('line', { x: laneX, y: 1.6, w: 0, h: 5.0, line: { color: t.line, width: 1 } });
```

**配色建议**：科技深蓝/极简灰白；图内字号 ≥10pt；**禁**装饰性大色块（图密度已高）。
